Ghostunnel releases ship with a Software Bill of Materials (SBOM) listing
the Go modules compiled into each binary, including the Go standard library
version. SBOMs are generated from the compiled binaries themselves (via the
Go build information embedded by the toolchain), so they reflect exactly
what was linked into a given artifact.

## Release binaries

Each binary on the [GitHub releases page][releases] has two SBOM files next
to it, in [SPDX 2.3][spdx] and [CycloneDX][cyclonedx] JSON format:

| Asset | SBOM files |
|-------|------------|
| `ghostunnel-linux-amd64` | `ghostunnel-linux-amd64.spdx.json`, `ghostunnel-linux-amd64.cdx.json` |
| `ghostunnel-darwin-universal` | `ghostunnel-darwin-universal.spdx.json`, `ghostunnel-darwin-universal.cdx.json` |
| `ghostunnel-windows-amd64.exe` | `ghostunnel-windows-amd64.exe.spdx.json`, `ghostunnel-windows-amd64.exe.cdx.json` |

The same pattern applies to every other binary in a release. The SPDX
document also records the SHA-256 checksum of the binary it describes, so you
can confirm which file an SBOM belongs to:

```bash
jq -r '.files[0].checksums[] | select(.algorithm=="SHA256") | .checksumValue' ghostunnel-linux-amd64.spdx.json
sha256sum ghostunnel-linux-amd64    # shasum -a 256 on macOS
```

To list the modules in a binary:

```bash
jq -r '.packages[] | "\(.name) \(.versionInfo)"' ghostunnel-linux-amd64.spdx.json
```

## Docker images

Images published to Docker Hub carry an SBOM attestation generated by
BuildKit, attached to the image index alongside the provenance attestation.
It covers both the Ghostunnel binary and the packages of the base image
(Alpine, Debian or distroless).

To retrieve it:

```bash
docker buildx imagetools inspect ghostunnel/ghostunnel:latest --format '{{ json .SBOM }}'
```

## Generating SBOMs locally

The release SBOMs are produced by the `sbom:generate` build target, which
requires [Syft](https://github.com/anchore/syft) on your `PATH`:

```bash
brew install syft            # or see the Syft README for other platforms
go tool mage go:build
go tool mage sbom:generate ghostunnel
```

This writes `ghostunnel.spdx.json` and `ghostunnel.cdx.json` next to the
binary.

## The observer ring

This fork publishes no releases; its proxy is built from source
(`deploy/README.md`, "Install"). The release SBOMs above cover upstream's
binaries only, which carry no ring and are not this proxy, so their
checksum never matches it. The operator takes `GT_EXPECT_BINARY_SHA256`
where the build is produced and reviewed, before the binary is copied to
the host: `sha256sum` of the build output there, or the SHA-256 in the
SPDX document `go tool mage sbom:generate <build output>` writes beside
that output. Run `sbom:generate` on the build output, not on the installed
`/usr/local/bin/ghostunnel`, or it writes its documents into
`/usr/local/bin`. The material member halts the ring unless the proxy's
executable hashes to that value. See `deploy/README.md`, "Two files, two
sources".
